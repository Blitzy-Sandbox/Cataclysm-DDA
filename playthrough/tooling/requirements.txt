# Python dependencies for the playthrough capture and cinematography
# pipeline (playthrough/tooling/).  Declared here rather than under
# src/, which carries no Python declaration of any kind.
#
# requirements.lock beside this file is the INSTALL contract: the same
# six pins plus their whole transitive closure, each bound to one
# wheel's sha256, under --require-hashes and --only-binary :all:.  This
# file is the DECLARATION, and it carries no pip option, no index and no
# hash.  The interpreter is CPython 3.12: numpy and Pillow ship
# per-interpreter binaries and the lock names cp312 wheels.
#
# Pins are exact rather than the floating lower bound of the
# repository's other requirements file, because this pipeline emits a
# byte-level media artifact AND its own acceptance evidence -- a
# floating bound would let a future release change the film while every
# gate still reported green.
#
# Installation, provisioning rules, the measured host inventory and the
# supported-container route are in playthrough/README.md.

moviepy==2.2.1  # fade/card/fade transition unit: make_transitions.py
pillow==11.3.0  # PNG inspection, title card, MoviePy 2 image backend
pytesseract==0.3.13  # sidebar clock OCR wrapper: ocr_clock.py
numpy==2.5.1  # frame luminance statistics and MoviePy arrays

# Pillow is held at the newest release the declared render stack admits:
# moviepy 2.2.1 requires `pillow<12.0`, and 2.2.1 is the newest moviepy.
# ocr_clock.py holds the same value as PILLOW_MIN_VERSION, and env.sh's
# closure check FAILS the day a moviepy release lifts that bound, so the
# justification for the pin cannot quietly become false.
#
# THE ADVISORY LEDGER BEHIND THAT ACCEPTED RISK, measured 2026-08-12
# against 11.3.0.  Fourteen distinct CVE identifiers were established as
# covering this release; a record count in OSV runs higher, because it
# carries a GHSA and a PYSEC entry for one and the same CVE.  NOT ONE of
# the fourteen is reachable here, and the ground is grouped below by the
# Pillow surface that shuts it out rather than restated per record --
# because the surface is a property of THIS TREE that a reader can check
# line by line, and it goes on holding for records published after the
# date above.
#
# (a) Every decoder except PNG: never entered.  All three Image.open
#     calls pass formats=["PNG"] over an in-memory buffer, so Pillow
#     loads the PNG plugin alone and no other plugin is ever built
#     [ocr_clock.py:1153,1181][make_transitions.py:1400].
#       CVE-2026-25990  PSD out-of-bounds write        fixed 12.1.1
#       CVE-2026-40192  FITS GZIP decompression bomb   fixed 12.2.0
#       CVE-2026-42311  PSD memory corruption          fixed 12.2.0
#       CVE-2026-55380  GD 2.x header bomb             fixed 12.3.0
#       CVE-2026-59200  PDF FlateDecode zlib bomb      fixed 12.3.0
#       CVE-2026-59203  EPS byte count, endless loop   fixed 12.3.0
#       CVE-2026-59204  JPEG2000 tiled scratch buffer  fixed 12.3.0
#
# (b) The font compilers: never entered.  The one font call is
#     ImageFont.truetype() on the attested interface face
#     [ocr_clock.py:874].  Nothing calls FontFile.compile(), and no PCF
#     or BDF font is opened anywhere in the tree.
#       CVE-2026-54059  PCF glyph metrics bomb         fixed 12.3.0
#       CVE-2026-54060  FontFile.compile() bomb        fixed 12.3.0
#       CVE-2026-55379  BDF BBX bomb                   fixed 12.3.0
#
# (c) The coordinate, filter and colour APIs: never reached with a
#     value from outside.  The one drawing call has a constant origin,
#     ImageDraw.Draw(cell).text((0, 0), ...) [ocr_clock.py:1241];
#     there is no ImagePath, polygon, line, rank filter or ImageCms
#     anywhere, the only filter being a GaussianBlur of a fixed radius
#     [ocr_clock.py:2382].  The crop and paste boxes
#     [ocr_clock.py:1427,2398,2405,2414,2664] are the computed sidebar
#     rectangle and whole multiples of one row height, taken from the
#     frame's own dimensions, and open_png sets
#     Image.MAX_IMAGE_PIXELS to MAX_PIXELS (64 Mpx) before any of them
#     runs, so no dimension reaches the signed 32-bit edge these need.
#       CVE-2026-42309  ImagePath/polygon/line write   fixed 12.2.0
#       CVE-2026-59197  RankFilter expand() overflow   fixed 12.3.0
#       CVE-2026-59199  paste/crop coordinate write    fixed 12.3.0
#       CVE-2026-59205  ImageCms apply() mode clash    fixed 12.3.0
#
# That enumeration is a dated snapshot and NOT a completeness claim:
# the same 12.3.0 batch carries CVE-2026-54058 and CVE-2026-59198,
# whose affected ranges were not established at this measurement, and
# more will be published.  It changes nothing available to do here.
# Every fix named above -- 12.1.1, 12.2.0 and 12.3.0 alike -- lies
# outside moviepy 2.2.1's own `pillow<12.0`, so no pin move can close
# any of them while this render stack is the declared one.  The
# ceiling, not the ledger, is what has to lift first, and env.sh's
# closure check is what fails on the day it does.

# "imageio" is lowercase on purpose: `pip list --format=freeze` prints
# "ImageIO" from the distribution's declared Name metadata, while the
# install and import name is lowercase.
imageio==2.37.4  # frame and video IO used by MoviePy

# The sixth entry is not one of the five libraries the requirement
# names.  It is declared because MoviePy and imageio encode through it
# and the render stage fails without it.  Its bundled static ffmpeg is
# never the one used: env.sh exports IMAGEIO_FFMPEG_EXE to the verified
# system binary, which is the only supported way to override
# get_ffmpeg_exe(), so that export has to stay set.
imageio-ffmpeg==0.6.0  # encoder bridge for MoviePy and imageio
